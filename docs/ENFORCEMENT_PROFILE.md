# Enforcement profile by entrypoint

Which checks run on which path, derived from the source (file references are to the code at the time of writing).
The deterministic core — validator, solver, compiler, verifier, approval derivation at contract time; the SQL
evaluator, budgets and capabilities at runtime — is the same on every path. Optional, model-based checks differ.

## Contract time

| Check                                              | Backend `POST /tasks/{id}/prepare`                                                | Dashboard propose                                                     | Dashboard activate                                                                                 |
| -------------------------------------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Plan validator, minimum-authority solver, compiler | runs (`gateway/prepare-task.ts`)                                                  | runs (`app/app/tasks/[taskId]/contract/actions.ts`)                   | re-runs and must reproduce the stored hashes                                                       |
| Contract verifier (consistency check)              | runs                                                                              | runs                                                                  | re-runs                                                                                            |
| Approval rules (admin-defined)                     | runs; a match leaves the contract `awaiting_approval`                             | runs                                                                  | re-runs; the database also checks each approval                                                    |
| Task-alignment plan review                         | runs if the application's alignment mode is shadow/enforce and plan checks are on | **not run**                                                           | not run in code; the database activation gate requires a cleared review when alignment is enforced |
| Jev necessity / completeness                       | **not run** (stated scope limit in `prepare-task.ts`)                             | runs if `jev_settings.necessity_mode` is on and a model is configured | re-runs under the current setting                                                                  |
| Excluded steps reported                            | yes (`excludedSteps`)                                                             | per-node findings in the UI                                           | n/a                                                                                                |
| AI-drafted plan (`generate: true`)                 | compiled directly; `ai_unavailable` without a model key                           | shown for human review, not compiled                                  | n/a                                                                                                |

## Runtime

| Check                                                                                | `/authorize`                                                              | `/execute` (connectors)                                                              | `/github/execute` | `/capabilities/consume`                         | MCP `tools/call`                               |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------- | ----------------------------------------------- | ---------------------------------------------- |
| Credential and task binding                                                          | runtime key or task session; session only for its task                    | capability bound to agent, task, tool, operation, resource and arguments             | same              | same                                            | via `/authorize`                               |
| Require task sessions (application setting)                                          | enforced                                                                  | —                                                                                    | —                 | —                                               | enforced (via authorize)                       |
| Deterministic SQL decision (contract, pinned values, closed-world arguments, budget) | yes, committed under the task lock                                        | capability re-validated; contract, task, agent and connection re-checked at dispatch | same, at dispatch | capability re-validated inline                  | yes                                            |
| Per-call task alignment                                                              | if enabled; enforce blocks before commit, shadow runs after (best effort) | —                                                                                    | —                 | —                                               | yes                                            |
| Semantic / Jev risk                                                                  | semantic if enabled (narrow-only); Jev risk shadow only                   | —                                                                                    | —                 | —                                               | yes                                            |
| Capability                                                                           | issued on a final allow                                                   | spent                                                                                | spent             | spent as simulated; refused for connector tools | issued and spent in one call                   |
| Budget refund when never dispatched                                                  | —                                                                         | yes                                                                                  | yes               | —                                               | —                                              |
| Connector-result screening                                                           | —                                                                         | if content checks are on                                                             | same              | —                                               | yes                                            |
| Idempotency                                                                          | caller key                                                                | caller key                                                                           | caller key        | caller key                                      | generated per call (retries not de-duplicated) |

Discovery: `GET /tasks/{id}/tools` and MCP `tools/list` apply the same credential, session and tenant check
(`gateway/task-access.ts`).

## Settings

| Setting                                                                         | Read by                                                                         |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `alignment_settings` (mode, policy, plan/action/content checks, content action) | backend prepare, authorize, MCP, execute screening, `/content`, activation gate |
| `applications.require_task_sessions`                                            | authorize, MCP, `/tools`, alignment calls                                       |
| `jev_settings.necessity_mode`                                                   | dashboard propose and activate only                                             |
| `jev_settings.risk_mode` (off/shadow only)                                      | authorize, MCP                                                                  |
| `semantic_settings`                                                             | authorize, MCP                                                                  |
| Custom API auto-execute opt-in                                                  | authorize, MCP (removes only the registry approval default)                     |
| Admin approval rules                                                            | prepare, dashboard propose and activate                                         |

## Known divergences

| Divergence                                                                                                                                                                                                                  | Status                                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MCP `tools/list` served a task's catalog for any bearer string                                                                                                                                                              | fixed: shared access check (#72)                                                                                                                                                                                     |
| Simulated `/consume` accepted capabilities for non-GitHub connector tools                                                                                                                                                   | fixed: refused (#74)                                                                                                                                                                                                 |
| GitHub release before dispatch kept the step's budget held                                                                                                                                                                  | fixed: refunded like other connectors (#73)                                                                                                                                                                          |
| A capability revoked while its write was in flight (by its agent, an administrator or a disconnect) had the use refunded, so the step could be authorized again beyond `maxInvocations` (reproduced with the mock provider) | fixed: settlement counts any dispatched execution (#81, migration `20261023000003`)                                                                                                                                  |
| Backend prepare skips Jev; dashboard propose skips task-alignment plan review                                                                                                                                               | documented; inferred consequence: with alignment enforce + plan checks, a dashboard-proposed contract cannot activate (the activation gate needs a plan review the dashboard never creates). Not verified by a test. |
| Dashboard propose compiles from the Jev-adjusted validation, but the verifier re-derived from the mechanical one, so any Jev enforce narrowing failed verification (reproduced)                                             | fixed: the verifier accepts the adjusted validation only as a proven narrowing (#76)                                                                                                                                 |
| MCP generates idempotency keys per call                                                                                                                                                                                     | documented limitation                                                                                                                                                                                                |
| Alignment enforcement at commit is chosen in application code (`gateway.commit_authorization_aligned`), not by the base commit function                                                                                     | by design: only the gateway role can call either                                                                                                                                                                     |
